# 软件指南生成器

SwiftUI 写的 macOS 原生 App，是现在唯一维护和发版的版本。功能和 Electron 旧版一致；Electron 旧版定档在 git 标签 `electron-v0.1.0-final`，不再修改、不再发版。

## 打包和运行

需要 Xcode 27（macOS 27 SDK），App 最低支持 macOS 26。

```bash
scripts/build-app.sh            # 生成 dist/软件指南生成器.app
scripts/build-app.sh --test     # 先跑全部测试再打包
scripts/build-app.sh --zip      # 另外打一个 zip
```

产物是 arm64 + x86_64 通用包，ad-hoc 签名，只适合自己的 Mac 用；拷到别的 Mac 第一次打开要在「系统设置 → 隐私与安全性」里放行。装到「应用程序」时，Electron 旧版改名为「软件指南生成器（Electron 旧版）.app」，两个可以同时存在。

开发时用 Xcode 打开 `ManualStudio.xcodeproj` 直接运行，或者：

```bash
xcodebuild -project ManualStudio.xcodeproj -scheme ManualStudio -configuration Debug -derivedDataPath build/DerivedData build
```

指南 PDF 和原有 TXT 代码模式靠 LibreOffice 转换，没装时「设置 → 通用」里会提示。

## 指南截图完整排版（v1.4.6）

- 截图根据左栏扣除内边距后的宽度、页面高度和图注空间等比例缩放；固定左右栏宽，不裁图、不拉伸。
- 已有指南可在「交付 → 重新导出 PDF」或历史项目批量重新导出时检查排版。旧版截图超宽时先使用已有截图和正文重排指南 Word，再转 PDF，无需 AI；新布局的 Word 不重复改写。
- 原 Word 的正文和图片必须与项目源文件一致，否则停止并保留原包，避免覆盖手工编辑。缺少 content.json 或截图也会明确失败。
- 全部转换成功后才替换文件；旧指南 Word（需要重排时）和 PDF 归档到项目 archive。TXT、代码 Word 和原截图保留。
- 验收与限制见 `../docs/验收-指南截图遮挡修复-20261015.md`。

## 内容日期与平台说明

- 「内容日期」是截图里的「今天」，默认本地新建当天；新建时（单个和批量）就能改。当前日期、日历选中日、最新一条记录和封面编制时间用这一天。
- 「最早日期」选填，可填企业成立或开发完成日期；不填时为内容日期前 30 天。流水、订单、缴费、动态等历史记录只能落在最早日期到内容日期之间，累计期数、连续天数也不能暗示更早就开始使用；预约、截止等未来安排可以晚于内容日期。出生日期、证件有效期这类与使用软件无关的日期不受限。
- 这条规则不只写在提示词里，程序会三处复核（v1.4.7）：规划的示例数据（生图前，不花生图费用）、截图上看图模型抄下的文字（早于最早日期就带着原因自动重生，次数用完交给人工确认）、正文（截图里本来就有的日期照实描述不算）。规划和正文的日期问题会让模型改，改不好也不会让整个项目失败。
- 在「项目 → 概览」可修改内容日期和最早日期（`YYYY-MM-DD`）。修改后点「继续运行」，统一重新规划、生成截图与撰写；上游更新完成前，单屏重生或只重写文字会提示先完成更新。v1.4.5 起新建的项目再次运行时会按新规则重新验收截图。
- 封面「编制时间」留空时跟随内容日期，仍可单独指定；重新导入项目时保留日期及自动/手动行为。已有历史材料不会因升级自动重新生图，需要时主动设置内容日期再运行。
- 「截图样式」只决定截图外观。软件名没有明确指定平台时，指南介绍、标题、功能正文和设计说明使用通用表述，不写 iOS、安卓或具体机型；手动改写后的材料也会在构建前校验。软件名称明确包含平台时保留该例外。
- TXT 的主要功能与指南介绍共用同一份内容；固定的运行硬件、运行平台和运行支撑环境字段统一省略，开发环境字段保留。

本轮验证记录见 `../docs/验收-日期与平台说明-20261015.md`。

## 修改意见（v1.4.7）

- 每条意见可以在「改哪里」里指定位置：某一张图、全部截图、封面介绍或设计说明；不指定就让软件判断。指定了就一定改那里。
- 软件判断时把每屏完整的画面描述、图上文字和说明交给大模型，默认直接执行，尽量不反问。大模型结果由程序补全：目标写错的纠正，漏掉的意见按原话补上。
- 整理失败（模型出错、格式不对）不再报错退出：指定了位置的意见照样列出，没指定的在确认窗口里选位置后「按原话改这里」。确认窗口里每一屏的修改可以在「改图 / 只改文字」之间切换。
- 改图后验收时，看图模型会核对这条修改有没有体现在图上；没改到就带着要求自动重生，次数用完交给人工确认。

## 数据

### 代码 Word 模板（v1.4.4）

「设置 → 代码来源 → 使用内置模板」启用软件自带的 Java 代码 Word 模板（3,322 行，其中 3,229 行非空）。也可选择符合要求的 `.docx` 代码模板；软件保存带 SHA-256 文件名的副本，下载文件移动后仍可使用。

- 完整保留代码文字、顺序及空白行，均衡分配到 60 页，页眉左边是项目软件名、右上角是「第 N 页」（v1.4.7 起；Word 用 PAGE 域，旧模板约定的「代码页眉不带页码」只对源码文件夹 / TXT 模式保留）。代码 PDF 使用 macOS 原生排版并嵌入可用字体；交付前检查必须正好 60 页、非空代码行数超过 3,000。模板不足或内容溢出则明确失败，保留旧交付材料。
- 内置模板实测正文 9 磅、A4、60 页。附带 Word 使用相同分页和所选字体；打印请使用生成的 PDF、每张一页，Word 在不同软件中重新排版可能改变页数。
- 历史项目勾选多个项目 →「更多 → 批量应用当前代码模板…」。只替换代码 Word、代码 PDF 及相关来源记录，指南、截图和正文保持原样，不调用 AI；旧材料先归档。运行中或排队中的项目跳过，单个项目失败不影响其余项目。
- 单项目也可在「交付 → 更换模板 → 改用设置里的模板」主动切换。只重新导出已有 PDF 不会自动应用总设置的新模板。
- 批量替换保存恢复日志；中断后下次启动先恢复。日志损坏时阻止进入正常操作，显示恢复错误，避免继续覆盖材料。
- 代码模板 PDF 无需 LibreOffice，完整指南生成仍需要。原有 TXT / 源码文件夹模式保留；本次正好 60 页规则适用于 Word 代码模板模式。模板导入支持单节、每段一行、纯文本软件名页眉；复杂表格、图片、修订或段内换行明确拒绝。

本次验收与未验证范围见 `../docs/验收-代码模板精确60页与批量更新-20261014.md`；v1.4.3 的旧验收记录保留以便追溯。

| | Electron 旧版 | 当前版本 |
|---|---|---|
| 项目文件夹 | `~/Desktop/软件指南生成` | 同一个，格式完全相同 |
| 软件数据（设置、线路、调用记录、项目列表） | `~/Library/Application Support/软件指南生成器` | `~/Library/Application Support/软件指南生成器（原生版）` |
| 密钥 | Electron safeStorage | `secrets.json` 加密保存，加密用的密钥在同目录的 `secrets.key`（权限 600），不经过钥匙串 |

- 软件数据目录的名字里仍带「（原生版）」，这是内部名字，为了不和 Electron 旧版混在一起，不要改。
- 密钥不放钥匙串：App 是临时签名，每次升级签名都会变，钥匙串会把新版本当成别的 App，弹窗要密码或读不到。1.4.1 之前存在钥匙串里的，第一次打开 1.4.1 时读一次转存到 `secrets.key`，之后不再访问钥匙串。两个文件都只在本机，不会上传。
- 第一次打开会问要不要导入 Electron 旧版的数据（设置、线路和密钥、调用记录、项目列表）。之后也可以在「设置 → 导入历史项目 → 从 Electron 旧版导入」再导一次，只合并新增的内容。
- 导入只读 Electron 的数据目录，不会改动它。导入密钥时 macOS 会弹窗询问是否允许读取「软件指南生成器 Safe Storage」，点允许即可。
- 两个版本共用项目文件夹，同一个项目不要两边同时运行。

## 在线更新

软件打开时会去 GitHub Releases（公开仓库 `deepfry666/manual-studio`）查新版本，6 小时内最多查一次；菜单「软件指南生成器 → 检查更新…」和「设置 → 通用 → 更新」可以手动检查，也可以关掉自动检查。有新版时弹窗显示更新说明，点「立即更新」后：下载 zip → 核对 GitHub 给的 SHA-256 → 核对包标识和版本号 → 退出 → 替换 App → 重新打开。有任务在跑时不会更新。App 所在的文件夹没有写权限时，新版本会放进「下载」文件夹让你手动替换。

## 版本规则

每次交付给用户的更新都递增可见版本号和构建号，普通修复递增补丁版本。当前为 **v1.4.7（构建 13）**：日期规则复核、修改意见指定位置、代码文档页码。Debug / Release 配置、打包产物与实际安装版版本必须一致；不能只替换代码而保留旧版本号。版本约束也记录在项目根目录 `AGENTS.md`。

## 发版

只发原生版。改完代码、提交之后：

```bash
scripts/release.sh 1.1.0             # 更新说明按提交记录自动生成
scripts/release.sh 1.1.0 notes.md    # 或者自己写更新说明
```

脚本会改版本号、跑测试、打包、提交并打标签 `v1.1.0`、推送到 GitHub，再建 Release 并上传 zip（文件名是 `ManualStudio-1.1.0.zip`，GitHub 不支持中文附件名，显示名是中文）。需要先 `gh auth login` 登录 GitHub。下载 zip 解压后，把 App 拖进「应用程序」替换旧的即可，数据不受影响。

```

├── App/                    SwiftUI 界面（ManualStudio target）
│   ├── Pages/              新建项目、历史项目、项目详情各标签、模型与线路、设置
│   └── Support/            AppModel（状态和事件）、通用组件、开发自检
├── StudioCore/             Swift Package，全部业务逻辑，不依赖界面
│   ├── Sources/StudioCore/
│   │   ├── Util/           和 JS 字节一致的 JSON、文本、文件、zip
│   │   ├── Gateway/        生图网关：并发、补发、切换、重试、熔断、异步任务续查
│   │   ├── LLM/            OpenAI 兼容客户端、JSON Schema 校验和修复
│   │   ├── Pipeline/       规划 → 提示词 → 生图 → 验收 → 文案 → 设计说明 → 审查回执 → 交付包
│   │   ├── Build/          Word（复刻 docx 库输出）、TXT、LibreOffice 转 PDF 和字体核对
│   │   └── Migration.swift 从 Electron 旧版导入
│   └── Tests/              105 个测试
└── scripts/
    ├── build-app.sh                 打 Release 包
    ├── release.sh                   发版到 GitHub Releases
    ├── generate-from-electron.mjs   从 Electron 代码生成提示词和 docx 固定部件
    └── make-fixtures.mjs            从 Electron 代码生成对照用的测试数据
```

## 和 Electron 旧版的一致性

- 提示词、JSON Schema 报错文字、Word 的 XML、TXT 模板都由 `scripts/` 从定档的 Electron 代码生成，测试逐字节对照（`CompatibilityTests`）。
- 每一步的输入哈希和 Electron 旧版算法相同，所以 Electron 旧版做到一半的项目可以在原生版接着跑，不会被当成改过而重做。`RealDataTests` 会只读地扫一遍本机 Electron 数据里的真实项目重新核对哈希。
- 网关、流水线、反馈修改、导入、导出、改名等用模拟的生图线路和大模型测试（`GatewayTests`、`PipelineTests`、`FeatureTests`、`EdgeTests`）。

```bash
cd StudioCore && swift test
```

## 开发自检

设置环境变量 `MS_DEV_CONTROL=<文件>` 启动时，App 会读这个文件里的指令切换页面（见 `App/Support/DevControl.swift`），配合截图逐页检查界面。`MS_DATA_DIR` 可以把软件数据换到别的目录，`MS_TEST_MEMORY_SECRETS=1` 让密钥只存在内存里、不写文件。
