# 原生版快速入门

本文面向 `native/` 下的 SwiftUI macOS App，按 v1.6.6 的源码与发布说明整理。Electron 旧版请查阅[历史说明](使用说明.md)。

## 1. 安装与检查环境

从 [GitHub Releases](https://github.com/deepfry666/manual-studio/releases) 选择原生版，下载 ZIP、解压并将「软件指南生成器.app」放到「应用程序」。

- App 最低运行版本：macOS 26。源码构建要求见 [native/README.md](../native/README.md)。
- 当前构建为 ad-hoc 签名，不应视为已经过 Apple 公证。若系统拦截，先核实发布者和下载来源，再按 macOS 的安全提示自行决定是否允许打开，不要关闭系统整体安全保护。
- 指南 PDF 需要 LibreOffice。在「设置 → 通用」查看检测状态，安装后可点「重新检测」。
- Word 代码模板的代码 PDF 使用原生排版；旧 TXT 代码模式转 PDF、导入 `.doc` 模板仍需要 LibreOffice。
- 在「设置 → PDF 与字体」检查可用字体和替代方案。不要从不可信来源下载字体，商业字体需有相应授权。

## 2. 配置模型与线路

### 生图线路

进入「模型与线路」添加生图线路，按服务商实际接口填写地址、模型、密钥及相应预设。不同服务的请求格式、图片尺寸和并发限制可能不同，不要只凭模型名称判断兼容。

首次使用以较低并发跑一个项目，确认返回结果、速度和费用后再批量处理。真实生图测速会发出生成请求，可能扣费。

### 大模型

添加厂商后，在「各步骤使用的模型」为下列任务选择模型并保存：

| 步骤 | 需要什么能力 |
| --- | --- |
| 规划界面 | 文字理解与结构化输出 |
| 截图验收与内容抄录 | 看图能力，能读取图片与图中文字 |
| 撰写说明文字 | 文字生成与结构化输出 |
| 设计说明（可选） | 文字生成与结构化输出 |

「测试」会调用接口并检查输出，不是免费额度保证。接口能连接不代表模型能正确完成看图或返回完整 JSON。

没有配置看图模型时，需要人工逐张确认图片；有看图模型也仍应人工核验最终内容。

### 注意费用与隐私

计费由你配置的服务商决定，软件不附送模型额度。模型测试、生成、重写、重试、图片重生与超时补发都可能产生费用；取消请求不一定撤销服务端计费。

生成所需的提示词、项目文字或图片会发送到所配置的服务商。只使用获准处理的数据。API 密钥只填在应用的配置界面，不要写进项目说明、截图、GitHub Issue 或共享日志。

## 3. 准备代码材料

当前版本提供「设置 → 代码模板」模板库，支持导入自己的 Word 模板；`.doc` 导入会借助 LibreOffice 转换。模板不随软件附带。

- 模板须来自你有权使用、且与目标软件材料相符的代码，不应拿无关模板证明软件实现。
- 当前 Word 模板模式按 A4、60 页、每页 50 个打印行排版；折行和空行计入打印行，不足要求或不支持的复杂结构会被拒绝。以应用校验结果为准。
- 超出模板页数要求时会选取相应片段，不代表代码完整性或登记合规已经审核。
- 可为新项目分配模板，也可在历史项目中「更新代码材料…」。这个操作不调用 AI。
- 在「设置 → TXT」核对开发环境、运行环境、编程语言和源程序量。当前模板路径有固定默认字段，**源程序量并非自动实测统计**；不要直接把默认值当作目标软件的真实信息。
- 旧项目的源码文件夹 / TXT 代码来源模式与 Word 模板模式规则不同，详情见[原生版说明](../native/README.md)。

## 4. 先做一个项目

1. 打开「新建项目 → 单个项目」，填写软件名（可带版本号）、截图数、重点功能与补充说明。
2. 检查内容日期、最早日期和截图样式。内容日期用于生成内容，不是软件开发或交付事实的证明。截图样式也不是应用实际运行平台的证明。
3. 初次尝试建议在「设置 → 通用」打开规划确认，再点「创建并开始」。否则默认流程可能直接继续生成并调用付费接口。
4. 核对规划是否符合真实软件，再继续。图片生成后查看验收结果；自动判断不可靠时按真实情况人工核对。
5. 在「编辑」逐屏检查图片和说明。直接编辑文字、请求「只改文字」和「改图」是不同操作；后两者会调用对应模型。
6. 到「交付」打开生成文件，检查排版、字体、正文和代码材料，然后再导出。

应用所称的「截图」由生成模型绘制，并非从你的实际软件自动截取。若材料要求真实运行截图，应使用真实软件采集并按要求整理，不能把生成图当作实机证据。

## 5. 批量前的核验清单

- [ ] 软件名、版本、功能、日期与实际软件一致。
- [ ] 每张图的文字可读，数据和操作逻辑合理，无虚构功能或未经授权的信息。
- [ ] 说明文字与实际软件、配图内容相符，不只是通过模型验收。
- [ ] 代码来源有权使用，且与目标软件相符；TXT 字段不是未经检查的默认值。
- [ ] 在实际使用的阅读器里打开 Word 和 PDF，检查分页、字体、图片和可读性。
- [ ] 已确认服务商收费、并发限制、自动重试和补发设置。
- [ ] 已备份项目与重要材料，再执行批量覆盖或更新。

检查单个项目后，再使用「批量新建」或历史项目的多选操作。批量「全部重做」会重新规划、出图和写文字，可能产生较多费用；「只重写文字」也会调用大模型。「已提交」项目保持只读，需要修改时先取消该标记。

本工具提供生成与排版辅助，不构成法律意见，也不保证软件著作权登记或其他审核通过。

## 常见问题

| 情况 | 先检查 |
| --- | --- |
| 提示没有密钥、鉴权失败 | 检查对应服务的密钥、接口地址和模型权限，不要反复发起收费任务 |
| 模型输出不是有效 JSON | 查看「模型与线路 → 调用记录」详情；核对结构化输出支持、输出长度与服务商余额 |
| 提示额度不足 | 先核查服务商账户额度或更换已授权线路 |
| 图片停在待确认 | 检查是否未配置看图模型，或自动验收后仍需要人工处理 |
| PDF 转换失败或字体警告 | 检查 LibreOffice 检测结果和「PDF 与字体」设置，再打开输出文件核验 |
| 代码模板被拒绝 | 检查打印行数和模板结构；复杂表格、图片、修订或段内换行可能不被支持 |
| 项目无法编辑或重跑 | 检查是否标为「已提交」，或仍在运行 / 排队 |

报告问题时请提供版本号、操作步骤和脱敏后的错误信息。日志可能包含模型返回或项目内容，分享前检查并移除密钥与私人数据。

## 文件、备份与旧版迁移

- 默认工作区：`~/Desktop/软件指南生成`，可在设置中更改。
- 原生版数据目录：`~/Library/Application Support/软件指南生成器（原生版）`。项目文件和应用数据不是同一个目录，备份时需分别考虑。
- 旧图片、文字历史和部分被替换的材料可在项目历史或 `archive/` 中找回，但不能把历史保留机制当作完整备份。
- 原生版密钥使用本地加密文件保存，加密密钥也在同一应用数据目录；这不等于目录泄露后仍安全。不要公开、上传或随意共享此目录。
- 导入 Electron 旧版前先备份。应用会用旧版设置替换原生版设置，并合并项目列表和调用记录，请先阅读确认框；旧版数据目录不被改写。
- 两版共享项目工作区，避免同时操作同一项目。Electron 旧版已停止维护，后续操作以原生版说明为准。
