# 软件指南生成器 使用说明

## 打开

- **打包好的 App：** `release/mac-arm64/软件指南生成器.app`，双击打开。可以拖进「应用程序」文件夹。
  - App 没有签名。第一次打开如果被系统拦下，在访达里右键 App →「打开」→ 再点「打开」。
- **开发方式：** 在项目文件夹里运行 `npm start`（先构建界面再启动）。

改了代码之后，运行 `npm run dist` 重新打包 App。

## 菜单

| 菜单 | 内容 |
|---|---|
| 项目 | 所有项目；运行进度、排队、用时都在这里看；勾选后可以「开始处理」「导出…」「重新导出 PDF」 |
| 新建项目 | 顶部切换「单个项目 / 批量新建」 |
| 模型与线路 | 生图线路、大模型、调用记录 |
| 设置 | 常规（工作区、同时处理几个项目）、代码来源、PDF 与字体、导入历史项目、TXT 环境字段 |

## 第一次使用：配置

1. **生图线路（模型与线路 → 生图线路）：** 点「从旧 skill 导入」。会读取 `~/.codex/software-manual-image-providers.json`，把 CPA、APIMart 两条线路连同密钥导进来，旧文件不修改。也可以点「添加线路」手动添加。
   - 每条线路可以先点 🧪 测一下连通性（免费）。点 ⚡ 会真实生成一张图来测速，要扣一张图的费用。
2. **大模型（模型与线路 → 大模型）：** 添加厂商（DeepSeek、智谱、OpenAI 或其他 OpenAI 兼容接口），填好密钥后，在下方「各步骤使用的模型」里分别选：
   - **规划界面 / 撰写说明文字 / 设计说明：** 文字模型，比如 DeepSeek 的 `deepseek-chat`。
   - **截图验收与内容抄录：** 看图模型，比如智谱的 GLM-V 系列或 OpenAI 的模型。不配置的话，截图改为人工逐张确认。
3. **代码来源（设置 → 代码来源）：** 选一次源码文件夹或文件，所有项目共用。不设置时交付包只有说明书 3 个文件。
4. **导入历史项目（可选，设置 → 导入历史项目）：** 选中要导入的项目。
   - 导入只是在软件里登记，不复制、不改动项目文件夹。
   - 同时会把旧的生图耗时记录导入，作为补发线的初始数据。

## 做一个新项目

1. 「新建项目」，填写软件名（含版本号）。版本号自动识别，不用选。截图数可以让大模型决定，也可以指定。
2. 点「创建并开始」。默认会在规划完成后停下，请你在「规划」里看一眼，确认后再继续。这个行为可以在设置里关掉。
3. 之后自动执行：生成截图 → 验收 → 撰写文案 → 回执 → 构建交付包。项目页顶部实时显示当前步骤、每张截图的状态、已用时和预计剩余时间。
4. 跑完会提示用时。每个项目的「完成用时」显示在项目列表的「用时」列、项目页标题旁边和「概览 → 用时」（含每次运行、各步骤用时），也写进项目文件夹的 `generation-record.json`。
5. 交付包在项目文件夹的 `{软件名}/` 下。「交付」页可以逐个打开文件，也可以打包成 zip。

## 生图策略

- **真正并发：** 每张截图是一个独立任务，所有屏同时发出，不再等第 1 张生成完。
- **线路顺序：** 按「生图线路」页的顺序，选第一条可用的线路。
- **满载分流：** 首选线路的并发名额已满时，直接发给同一「画风组」里还有空位的线路，不在后面排队。可以在「生图策略」里关闭。
- **超时补发：** 某张图超过这条线路的「补发线」还没回来，会向另一条线路补发同一张，先出图的用。
  - **补发线怎么算：** 取这条线路最近 50 次成功耗时的第 85 百分位，限制在 20–120 秒之间。不足 5 次记录时用线路里设置的默认值。
  - **补发去哪条线路：** 默认只补发到同一个「画风组」的线路。比如 CPA 的 gpt-image-2.5 和 APIMart 的 gpt-image-2.5-flare 设成同一组。
  - **输掉的一边怎么处理：** 同步请求直接取消；异步任务不取消，出图后存成「备选图」，可以一键换上。
  - **费用：** 每次运行的补发数量有上限，设为 0 就是关闭补发。
- **失败处理：**

  | 情况 | 处理 |
  |---|---|
  | 5xx / 网络错误 | 同一线路重试 1 次，再换下一条 |
  | 额度用完（429、credential_quota） | 按报错里的剩余时间冷却，期间跳过这条线路 |
  | 模型不存在 / 鉴权失败 | 标为配置错误，测试通过后恢复 |
  | 连续失败 3 次 | 熔断 5 分钟 |
  | 只收比例、不收像素尺寸 | 自动改成最接近的比例并立即重试（864x1824 → 1:2） |

- **重启不重复扣费：** 异步任务的任务号一拿到就记下来，软件重启后继续查询，不重新提交。提交途中退出、没拿到任务号的，会在顶部提示「提交结果未知」。
- **调用记录：** 每次调用都保留，可以在「调用记录」里按线路看耗时和成功率。

## 代码文档

- 代码文档只使用「设置 → 代码来源」里的源码（文件夹或单个文件），所有项目共用。按文件路径排序后原样排版，格式和旧模板一致。软件不内置任何代码正文。
- 项目第一次生成交付包时，会记下当时用的代码来源（路径、行数、指纹）。之后改设置，**已完成的项目不会重建**，仍是原来的代码文档；还没生成交付包的项目用新的。
- 没有代码来源时，交付包只有指南的 Word、PDF、TXT，不包含代码文档。
- TXT 的【源程序量】按代码来源的实际行数统计；【编程语言】按代码文件类型判断。其余环境字段的默认值和旧模板一致，可以在「设置」或项目的「交付」里修改。
- 导入的历史项目里，代码文档来自旧 skill 内置的固定正文。
- **构建会先停下确认：** 历史项目的交付包里有代码文档、但项目没有代码来源时，重新生成交付包会停下来。在项目的「交付」里选择：
  - 「改用总设置的代码来源」；
  - 「确认不含代码文档」。

  批量运行时也一样，不会悄悄生成一个不含代码文档的交付包。
- **历史项目没有改动时：** 点「检查并更新」不会改写任何文件，也不会重建。

## PDF 字体

- 模板里说明书用「微软雅黑」、代码文档用「新宋体」，Mac 上没有这两个字体。以前 LibreOffice 会随便抓一个中文字体顶上，每次转出来都不一样（圆体、楷体、娃娃体都出现过）。
- 现在：
  - 装了原版字体就用原版。
  - 没装就固定换成系统字体：说明书用苹方，代码文档用华文宋体。在「设置 → PDF 与字体」里可以换。
  - 转完会核对 PDF 里实际用的字体。不对就在交付页和项目列表里标「PDF 字体不对」。
- 用替代字体时，代码文档的页数会和原版不同，因为模板是单倍行距，行高跟着字体走。想完全一致，需要在「设置 → PDF 与字体」里安装原版字体文件（`msyh.ttc`、`msyhbd.ttc`、`simsun.ttc`）。这两个是微软的商业字体，软件不能自带。
- 已经做好的项目：在项目列表勾选，点「重新导出 PDF」。只用现有 Word 重转 PDF，Word、TXT 不动，旧 PDF 移到项目的 `archive/`。

## 修改意见

只有一个入口：项目页顶部的「修改意见」。

1. **攒清单：** 看到问题就写一条，点「加入清单」（或 ⌘+回车）。这一步先不执行。可以写很多条、分几次写，比如「图3 底部按钮改成蓝色」「图5 说明多写异常处理」「整体颜色淡一点」。
2. **整理：** 点「整理意见并统一修改」。大模型把所有意见合并成具体动作：
   - 同一屏的多条意见合成一次修改；
   - 「整体」类意见展开成每一屏；
   - 说不清改哪里的意见单独列出来问你。
3. **确认：** 每个动作可以取消勾选、改措辞。底部显示一共要重生几张图、重写几段说明。
4. **统一改：** 确认后一次跑完：
   - 要重生的截图同时生成、一起验收；
   - 再一起重写说明；
   - 最后只构建一次交付包。
5. **留记录：** 执行过的意见标成「已处理」；需要你补充的继续留在清单里。意见原文和具体改了什么都写进 `generation-record.json`。

## 常用编辑

| 想做的事 | 在哪里 | 会重做什么 |
|---|---|---|
| 某张截图不满意 | 截图 → 重新生成 | 只重生这一屏，重新验收；这一屏的说明文字会按新截图重写（人工改过的不覆盖） |
| 换成备选图 | 截图 → 备选图 | 重新验收这一屏，再重建交付包 |
| 改说明文字 | 文案 →「保存并更新交付包」 | 只重建交付包 |
| 没有看图模型时确认截图 | 截图 → 逐张「没有软件名，通过」 | 最后一张确认后自动继续 |
| 改界面规划 | 规划 → 编辑 | 只重生被改的那一屏 |
| 改软件名 | 项目名旁边的 ✏️ | 不重新规划、不重新生图；用新名字重新验收截图，然后重建；文件夹一起改名 |
| 加设计说明章节 | 概览 → 附加设计说明章节 | 生成设计说明，再重建交付包 |

## 批量

- **建项目：** 「新建项目」→「批量新建」，每行一个软件名。需要的话可以用逗号带上 `截图数,重点功能,补充说明`。也可以在项目列表里勾选已有项目，点「开始处理」。
- **同时处理几个：** 默认 3 个。在「设置 → 常规」或项目列表顶部的批量栏里调整。比如 50 个项目设 3，就是 3 个同时跑，跑完一个补一个。生图总并发由生图线路控制，所有项目共用，调大项目数不会把线路挤爆。
- **自动跑：** 批量项目跳过规划确认，直接跑到交付包。排队、运行、完成情况都在「项目」列表里看。
- **断点续跑：** 软件中途关闭，下次打开自动续跑。

## 批量导出

- 在项目列表勾选项目点「导出…」，或者直接点「导出全部已完成」，再选导出位置（会记住上次的位置）。
- 每个项目导出成一个文件夹，文件夹名就是项目名，里面是交付文件：有代码文档 5 个，没有 3 个。只复制，不改动原项目。
- **导出位置已有同名文件夹时会先提醒你选：**
  - 跳过这些项目，已有的文件夹不动；
  - 覆盖：已有的文件夹先移到废纸篓，再导出新的。
- 没有交付包的项目会跳过并列出原因；PDF 字体不对、项目还没跑完的会标出来。

## 数据放在哪里

- **项目文件：** 在工作区（默认 `~/Desktop/软件指南生成`，和旧 skill 同一个文件夹），文件结构和旧 skill 一样。被替换的旧截图和旧交付包归档在项目的 `archive/` 里。
- **溯源：**
  - 项目文件夹里的 `generation-record.json` 记录每张截图由哪条线路、哪个模型、什么时候生成（含图片哈希），验收用的是看图模型还是人工确认，各步骤用的是哪个大模型，以及按时间顺序的事件。
  - 构建时把这些来源汇总写进 `project-manifest.json` 的 `provenance` 字段。
  - 历史项目在软件里第一次生成或修改东西时才会出现这份记录，导入本身不写任何文件。
  - 每一次生图调用的明细（包括失败、补发、取消的）在「调用记录」页。
- **软件自己的数据：** `~/Library/Application Support/软件指南生成器/`，包括设置、加密的密钥、调用记录、项目状态和任务账本。
- **密钥：** 用系统钥匙串加密保存。重新打包 App 后第一次读取时，系统可能会询问是否允许访问钥匙串，点「始终允许」即可。

## 开发

- `npm test`：运行全部测试。用本地模拟中转站和模拟大模型，不会调用真实接口、不花钱。
- `core/`：核心逻辑，不依赖 Electron。
- `electron/`：桌面壳。
- `web/`：界面（React + antd）。
- `core/templates/`：从旧 skill 复制来的排版模板。只打了两个补丁：截图行不跨页；代码正文从代码来源读取。字体不在模板里改，PDF 转换时用 LibreOffice 的临时替换表处理（`core/build/fonts.mjs`）。
